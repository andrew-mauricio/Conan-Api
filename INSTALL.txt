HOW TO INSTALL — read these 20 lines before copying anything
=============================================================

WHAT THIS IS
    Conan-Api is a server-side plugin framework for privately operated
    Conan Exiles Enhanced DEDICATED SERVERS. It runs inside the dedicated
    server process, on the machine you administer. Players connect with an
    unmodified client and download nothing.

    It is not a client mod, not a Workshop item, and there is nothing for
    your players to install.

HOW IT GETS INTO THE SERVER PROCESS
    By DLL proxying (import forwarding) — the same mechanism ArkApi and
    AsaApi use. You rename the Windows winmm.dll that is already in the
    server's binary folder, and put ours in its place. Ours forwards every
    exported call to the renamed original, so the game loses nothing, and
    initialises the plugin runtime alongside it.

    Steps 3 and 4 below are exactly that, and nothing more.

YOU HAVE TWO ITEMS HERE

    winmm.dll     <- the loader. NOTHING WORKS WITHOUT IT.
    Conan-Api/    <- the runtime, the plugins, the SDK and the docs

STEP 1 — stop the server.

STEP 2 — go to the server executable's folder:
    <server>/ConanSandbox/Binaries/Win64/

STEP 3 — rename the winmm.dll ALREADY THERE (the system one) to:
    winmm_orig.dll

    If a winmm_orig.dll already exists, STOP: you have installed before.
    Renaming again chains the loader to itself, and the server dies
    silently (no log, no error, exit 1). Delete only the new winmm.dll
    and start again from this step.

STEP 4 — copy into that same folder:
    winmm.dll     (the loader, the one shipped here)
    Conan-Api/    (the whole folder)

STEP 5 — start the server and check:
    Conan-Api/Logs/ConanLoader.log   <- says whether the loader got in
    Conan-Api/Logs/ConanApi.log      <- says which plugins loaded

If the logs are not created, the loader did not get in: review step 3.

    NOTE: the runtime verifies the game build before loading anything. If
    the build is not one it has been validated against, it REFUSES to load
    and writes the reason to the log. That is deliberate — see the README
    section "Build compatibility".

BEFORE YOU INSTALL A THIRD-PARTY PLUGIN
========================================

A plugin is a native DLL running inside the server process, with that
process's privileges. There is no sandbox between plugins.

An installed plugin can read and modify anything in the server's memory,
see your players' identity data, write any file the server user can reach,
open network connections, and crash the server.

Install plugins you trust, preferably ones that publish their source, and
audit them as you would any other native server extension.

HOW TO INSTALL A PLUGIN YOU DOWNLOADED
=======================================

Each plugin comes in a folder. You drag the whole folder into:

    Conan-Api\Plugins\

That is all. No file to edit, nothing to switch on. Restart the server and
it loads.

It ends up like this:

    Conan-Api\
       Plugins\
          Permission\           <- ships with the API, it is the default
             ConanPermission.dll
             config.json
          PluginYouDownloaded\  <- you dragged this folder in
             PluginYouDownloaded.dll
             config.json

To UNINSTALL: delete the plugin's folder. That is it.

To DISABLE without deleting (for example, to test whether it is the cause
of something): create an empty file named DESLIGADO inside its folder.

If a plugin does not load, Conan-Api\Logs\ConanLoader.log gives the reason
with the folder name.

    NOTE: loader and runtime log messages are currently written in
    Portuguese. Translating them is planned; it is a code change and is
    tracked separately from this documentation.
